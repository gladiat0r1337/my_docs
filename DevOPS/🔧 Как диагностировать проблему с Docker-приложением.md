

**Принцип: наблюдение → гипотеза → проверка → исправление → повторная проверка.**

1. Проверить состояние контейнеров: `docker ps -a`.
    
2. Посмотреть логи проблемного контейнера: `docker logs --tail 100 <container>`.
    
3. Проверить переменные окружения и конфигурацию (не раскрывая секреты).
    
4. Проверить зависимости приложения: БД, Redis, внешние сервисы.
    
5. Проверить сети через `docker network inspect <network>`.
    
6. Проверить доступность TCP-портов через `nc -vz <host> <port>`.
    
7. Проверить HTTP-ответ приложения через `curl -i <URL>`.
    
8. После исправления провести smoke test основной функции.
    

**Важно:** статус `Up` не означает, что приложение исправно. Успешное TCP-подключение не подтверждает аутентификацию, а ответ HTTP 200 сам по себе не гарантирует правильность данных.
